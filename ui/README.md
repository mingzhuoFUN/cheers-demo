# 干杯！移动端 UI 交接

这个文件夹是当前已经确认的独立 UI 模块。后续开发后端时，建议只给 `CheersUI.tsx` 注入数据与事件，不重做现有布局和视觉样式。

## 文件

- `CheersUI.tsx`：完整手机端交互原型与页面状态。
- `cheers-ui.css`：颜色令牌、移动端布局、卡片、跳灯光圈和动效。
- `../app/page.tsx`：只负责加载 UI，不包含业务实现。
- `../public/avatar-explorations/avatar-direction-b-sticker.webp`：玩家头像精灵图。
- `../public/mode-cards/truth-landscape.webp`：真心话卡牌素材。
- `../public/mode-cards/dare-landscape.webp`：大冒险卡牌素材。

## 已完成的 UI 流程

1. 设置页
   - 2–6 人选择。
   - 玩家昵称编辑。
   - 男 / 女二选一。
   - 关系温度滑杆。
2. 跳灯页
   - 人物 ID 卡片根据人数自动分成上下区域并填满屏幕。
   - 中央矩形“开始游戏”作为上下区域分隔。
   - 跳灯光圈作用于整张 ID 卡片，而不是只框头像。
   - 动画由快到慢并落到最终玩家，避免连续两轮选中同一人。
3. 模式选择页
   - 真心话、玩家 ID、大冒险纵向排列并填充屏幕。
   - 使用已确认的真心话 / 大冒险视觉素材。
4. 题目页
   - 点击模式后进入独立整页，不使用弹窗。
   - 真心话使用蓝色卡，⼤冒险使用橙色卡。
   - 支持换题和点击进入下一轮。
5. 返回状态
   - 跳灯页返回设置页。
   - 模式选择页返回本轮跳灯结果。
   - 题目页返回模式选择页。
   - 返回箭头悬浮在首张卡牌左上角内部，不单独占据布局空间。

## 已确认的视觉原则

- 以 393 × 852 手机视图为设计基准。
- 重视觉、轻文字，不增加解释性导航和冗余文案。
- 奶油色背景、蓝橙双色、深蓝硬阴影和实体桌游卡牌感。
- 页面背景铺满设备四角，不显示设计画板式灰色外框。
- 不再使用会限制内容布局的对角蓝色装饰块。
- 卡片与玩家区域优先填满可用高度，避免下半屏大面积空白。

## 当前临时前端数据

`CheersUI.tsx` 内的玩家、题库、随机选择和状态切换仍是本地数据。接入后端时可替换为：

- 玩家创建、更新与房间同步接口。
- 题库获取与关系温度筛选接口。
- 服务端随机结果或多人实时广播。
- 游戏轮次、历史记录与断线恢复。

建议保留现有 `Phase` 流程：

`setup → ready → spinning → choice → question → ready`

## 后端对话可直接使用的说明

> 现有 UI 已放在 `ui/` 文件夹。请先阅读 `ui/README.md` 和 `ui/CheersUI.tsx`，在不改变视觉布局的前提下设计并接入后端。优先把本地玩家、题库、随机选择和游戏状态替换为明确的数据接口。
